Schema v1 is defined by the SQLAlchemy models and created at startup via Base.metadata.create_all. For this local small application no destructive migration is run. Back up named db-data before modifying schemas.

Schema v2 adds the household-cluster pre-registration tables (`cluster_studies`, `cluster_members`, `cluster_plans`, `cluster_claims`, `cluster_runs`). They are additive: existing `studies`/`observations`/`runs`/`reviews` rows are untouched, and `create_all` creates only the missing tables on startup. `cluster_claims.household_key` is globally unique and enforces cross-plan household exclusivity at the database level; `cluster_members` is unique on `(study_id, source_key)`. No column of the v1 tables changed, so a running v1 database upgrades in place without data loss.
